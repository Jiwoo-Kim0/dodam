# 외부 서비스 정보

도담이 사용하는 외부 서비스의 용도, 가입·발급 절차, 필요한 설정값을 정리한 문서다.
실제 키·토큰 값은 이 문서에 적지 않는다. 값은 EC2의 `infra/.env`(git 제외)와 EAS 환경 변수에만 둔다.
키 이름과 설명은 `infra/.env.example`, `frontend/.env.example`에 있다.

## 한눈에 보기

| 서비스 | 용도 | 사용하는 쪽 | 설정 키 |
| --- | --- | --- | --- |
| SSAFY 금융망 API | 사용자 계정, 계좌·카드·대출·예적금·거래, 신용등급 조회, 이체 | Backend | `SSAFY_FINANCE_API_KEY` |
| SSAFY GMS (OpenAI 중계) | AI 코치 "토리"의 문장 생성 | Backend | `OPENAI_API_KEY` |
| Google 로그인 (Google Cloud OAuth) | 소셜 로그인 | App, Backend | `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `GOOGLE_CLIENT_ID` |
| Kakao 로그인 (Kakao Developers) | 소셜 로그인 (백엔드만 구현, 앱 화면에는 없음) | Backend | `KAKAO_APP_ID` |
| Firebase Cloud Messaging | 푸시 알림 | App, Backend | `google-services.json`, `infra/secrets/fcm-service-account.json` |
| Expo / EAS | 앱 빌드와 APK 배포 | App | EAS 프로젝트 ID (`app.json`) |
| Let's Encrypt (certbot) | HTTPS 인증서 발급과 자동 갱신 | Infra | 없음 |
| Mattermost Incoming Webhook | 배포 실패와 서비스 이상 알림 | Infra | `MATTERMOST_WEBHOOK_URL` |

---

## 1. SSAFY 금융망 API

- **용도**: 교육용 모의 금융 데이터 원천. 사용자 계정 생성·조회(`userKey` 발급), 수시입출금·예적금·대출·카드 조회, 계좌 이체, 신용등급 조회에 사용한다.
- **Base URL**: `https://finopenapi.ssafy.io` (`application.yml`의 `app.ssafy-finance.base-url`)
- **가입·발급**: SSAFY 금융망 개발자 페이지에서 앱을 등록하고 API Key를 발급받는다.
- **설정**: `infra/.env`의 `SSAFY_FINANCE_API_KEY`
- **인증 방식**: 모든 요청 Header에 `apiKey`를 넣는다. 사용자 단위 API는 회원별 `userKey`를 함께 넣는다.
  `userKey`는 회원가입이나 금융 연결 시 금융망에 사용자를 생성해 받고, DB에는 암호문과 해시만 저장한다.
- **구현 위치**: `backend/.../infrastructure/external/ssafy/`
- **참고**
  - 타임아웃: 연결 3초, 읽기 5초
  - 금융망에는 사용자 삭제 API가 없다. 연결을 해제하면 도담 쪽 상태만 `DISCONNECTED`로 바뀐다.
  - 상세: `backend/docs/finance-data.md`

## 2. SSAFY GMS (OpenAI API 중계)

- **용도**: AI 코치(진단·추천·소비 예측 설명, "토리에게 묻기" 대화). 서버가 계산한 사실을 한국어 문장으로 바꾸는 데만 쓴다.
- **엔드포인트**: `https://gms.ssafy.io/gmsapi/api.openai.com/v1/chat/completions`
  중계 경로 규칙은 `https://gms.ssafy.io/gmsapi/<원래 호스트>/<원래 경로>`다.
- **모델**: `gpt-5.4-mini` (`max_completion_tokens` 600, `temperature` 0.2)
- **가입·발급**: SSAFY GMS에서 중계 토큰을 발급받는다.
- **설정**: `infra/.env`의 `OPENAI_API_KEY`에 **GMS 토큰**을 넣는다. OpenAI에서 발급한 키가 아니다.
  이 토큰으로 `api.openai.com`을 직접 호출하면 401이 나는데, 이는 정상이다.
- **인증 방식**: `Authorization: Bearer <GMS 토큰>`
- **참고**
  - 키가 비어 있으면 외부 호출 없이 템플릿 문장으로 응답한다. 서버는 정상 기동한다.
  - 비용 보호: 사용자별 시간당 40회(코치), 20회(대화) 상한. 응답은 Redis에 1시간 캐시한다.
  - 상세: `backend/docs/ai-coach.md`

## 3. Google 로그인 (Google Cloud Console)

- **용도**: 소셜 로그인. 앱이 Google Sign-In SDK로 ID token을 받아 서버에 보내면, 서버가 Google 공개키(JWK)로 서명과 `aud`를 검증한다.
- **가입·발급**
  1. Google Cloud Console에서 프로젝트를 만들고 OAuth 동의 화면을 구성한다.
  2. **웹 애플리케이션** 유형의 OAuth 클라이언트 ID를 만든다. 앱이 ID token을 요청할 때 쓴다.
  3. **Android** 유형의 OAuth 클라이언트 ID를 만든다. 패키지 이름(`com.ssafy.d105.dodam`)과 서명 인증서 SHA-1(EAS 빌드 키스토어 기준)을 등록한다.
- **설정**
  - 앱: `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` = 웹 클라이언트 ID
  - 서버: `GOOGLE_CLIENT_ID` = ID token의 `aud`로 허용할 클라이언트 ID. 여러 개면 쉼표로 구분한다.
- **Client Secret은 필요 없다.** 서버가 authorization code를 교환하지 않기 때문이다.
- **검증 엔드포인트**: `https://www.googleapis.com/oauth2/v3/certs`
- **참고**: `GOOGLE_CLIENT_ID`가 비어 있어도 서버는 기동하지만, 구글 로그인은 503(`SOCIAL_PROVIDER_UNAVAILABLE`)으로 실패한다.

## 4. Kakao 로그인 (Kakao Developers)

- **용도**: 소셜 로그인. 백엔드 API(`POST /api/v1/auth/social/kakao`)는 구현되어 있지만, **현재 앱 로그인 화면에는 카카오 버튼이 없다.** (구글 로그인과 개발용 로그인만 노출)
- **가입·발급**: Kakao Developers에서 애플리케이션을 등록하고 카카오 로그인을 활성화한다. 동의 항목에서 닉네임과 이메일을 설정한다.
- **설정**: `KAKAO_APP_ID` = 콘솔의 **앱 ID(숫자)**. REST API 키나 네이티브 앱 키와 다른 값이다.
  비어 있으면 "우리 앱에서 발급한 토큰인지" 검사만 생략하고 로그인은 동작한다.
- **검증 엔드포인트**: `https://kapi.kakao.com/v2/user/me`, `https://kapi.kakao.com/v1/user/access_token_info`
- **Client Secret은 필요 없다.**
- 상세: `backend/docs/auth-social.md`

## 5. Firebase Cloud Messaging (FCM)

- **용도**: 결제·상환 예정, 현금흐름 위험, 목표, 리포트 등의 푸시 알림
- **가입·발급**
  1. Firebase 콘솔에서 프로젝트를 만들고 Android 앱(패키지 이름)을 등록한다.
  2. `google-services.json`을 내려받아 `frontend/`에 둔다. EAS 빌드에서는 환경 변수 `GOOGLE_SERVICES_JSON`으로 파일 경로를 지정할 수 있다 (`app.config.js`).
  3. 프로젝트 설정 → 서비스 계정에서 **비공개 키(JSON)**를 생성한다.
- **설정**
  - 서버: 서비스 계정 JSON을 EC2의 `infra/secrets/fcm-service-account.json`에 둔다. `docker-compose.yml`이 이 파일을 읽기 전용으로 `/run/secrets/fcm-service-account.json`에 마운트하고, `FCM_SERVICE_ACCOUNT_PATH`도 그 경로로 지정한다.
  - 발송은 prod 프로필에서만 켠다 (`app.notification.push.enabled`).
- **참고**: 서비스 계정 JSON은 비밀값이다. 저장소에 커밋하지 않는다. 상세: `backend/docs/notification.md`

## 6. Expo / EAS

- **용도**: React Native 앱의 클라우드 빌드와 내부 배포용 APK 생성
- **가입**: expo.dev 계정을 만들고, `frontend/`에서 `npx eas login`을 실행한다. EAS 프로젝트는 `app.json`의 `extra.eas.projectId`에 연결되어 있다.
- **빌드 프로필** (`frontend/eas.json`)

  | 프로필 | 산출물 | API 주소 | 개발용 로그인 |
  | --- | --- | --- | --- |
  | `development` | 개발 클라이언트 (내부 배포) | `https://j15D105.p.ssafy.io/api` | 켬 |
  | `preview` | APK (내부 배포) | `https://j15D105.p.ssafy.io/api` | 켬 |
  | `production` | APK | `https://j15D105.p.ssafy.io/api` | 끔 |

- **빌드 명령**: `npx eas build -p android --profile preview`
- **참고**: `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`처럼 소스에 두지 않는 값은 EAS 환경 변수(`environment`)로 넣는다.

## 7. Let's Encrypt (certbot)

- **용도**: `j15D105.p.ssafy.io`의 HTTPS 인증서
- **가입**: 별도 가입이 필요 없다.
- **동작**: `infra/docker-compose.yml`의 `certbot` 컨테이너가 12시간마다 `certbot renew --webroot`를 실행한다. nginx는 자체 reload 루프로 갱신된 인증서를 읽는다.
- **최초 발급과 경로**: `infra/nginx/certbot/`. 절차는 `infra/README.md`를 따른다.

## 8. Mattermost Incoming Webhook

- **용도**: Jenkins 배포 실패, 컨테이너 이상, cron 작업(백업 등) 결과 알림
- **발급**: Mattermost → Integrations → Incoming Webhooks에서 채널을 골라 생성한다.
- **설정**: `infra/.env`의 `MATTERMOST_WEBHOOK_URL`
- **참고**: Webhook URL만 있으면 누구나 채널에 글을 쓸 수 있다. URL을 비밀값으로 취급한다.
