# 도담 안드로이드 앱 빌드 가이드

도담 앱(React Native + Expo)의 APK를 만들어 Android 기기에 설치하는 절차를 정리한 문서다.
시연·QA에는 **EAS Build의 `preview` 프로필**로 만든 APK를 쓴다. EAS를 쓸 수 없을 때를 대비해 로컬 빌드 절차도 함께 둔다.

실제 키·토큰 값은 이 문서에 적지 않는다. 키 이름과 설명은 `frontend/.env.example`, 발급 절차는 [외부서비스.md](외부서비스.md)를 본다.

## 한눈에 보기

| 항목 | 값 |
| --- | --- |
| 앱 이름 / 패키지 | 도담 / `com.ssafy.d105.dodam` |
| 프로젝트 경로 | `frontend/` (모든 명령은 이 디렉터리에서 실행) |
| 프레임워크 | Expo SDK 57 (`expo` 57.0.19), React Native 0.86, React 19, TypeScript 6 |
| 빌드 방식 | EAS Build (클라우드). 저장소에 `android/` 폴더가 없는 managed 프로젝트 |

| Android 기준 | minSdk 24 (Android 7.0), targetSdk / compileSdk 36, NDK 27.1, AGP 8.12, Kotlin 2.1 |
| JS 엔진 / 아키텍처 | Hermes, New Architecture 활성 |
| 서명 | EAS가 관리하는 키스토어 (Expo 프로젝트 `d105-dodam/dodam`) |
| 서버 주소 | `https://j15D105.p.ssafy.io/api` (빌드 프로필에 고정) |

### 1-1. 공통

| 도구 | 버전 | 비고 |

### 1-2. 로컬 빌드(선택)에서 추가로 필요한 것

| 도구 | 버전 | 비고 |
| --- | --- | --- |

### 1-3. 저장소 준비

```bash
git clone https://lab.ssafy.com/s15-fintech-finance-sub1/S15P21D105.git
cd S15P21D105/frontend
npm ci
```

`package-lock.json`이 있으므로 `npm install` 대신 `npm ci`를 쓴다.

## 2. 설정 파일과 환경 변수

### 2-1. 저장소에 있는 파일

| 파일 | 역할 |
| --- | --- |
| `app.json` | 앱 이름, 패키지, 스플래시, 플러그인, EAS 프로젝트 ID |
| `app.config.js` | 환경 변수에 따라 `app.json`을 덮어쓴다. `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`가 있을 때만 구글 로그인 네이티브 플러그인을 붙이고, `GOOGLE_SERVICES_JSON` 경로가 있으면 그 파일을 Firebase 설정으로 쓴다 |
| `eas.json` | 빌드 프로필 3종 (아래 2-3절) |
| `google-services.json` | Firebase(FCM) Android 설정. 저장소에 포함되어 있다 |
| `assets/splash/transparent_splash.xml` | 릴리스 빌드용 스플래시 drawable. 없으면 빌드가 실패한다 (6절) |

### 2-2. 환경 변수

앱이 읽는 값은 `EXPO_PUBLIC_` 접두사가 붙은 세 개다. 빌드 시점에 JS 번들에 박히므로 **비밀값을 넣지 않는다.**

| 변수 | 용도 | preview/production 빌드에서 | 로컬 개발에서 |
| --- | --- | --- | --- |
| `EXPO_PUBLIC_API_BASE_URL` | 백엔드 주소. `/api`로 끝나야 한다 | `eas.json`에 고정되어 있어 따로 안 넣어도 된다 | `.env`에 직접 적는다 |
| `EXPO_PUBLIC_ENABLE_DEMO_LOGIN` | 로그인 화면의 "개발용 로그인" 노출 여부 | `eas.json`에 고정 (`preview`는 `true`, `production`은 `false`) | 개발 실행(`__DEV__`)에서는 값과 무관하게 항상 보인다 |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | 구글 로그인용 웹 애플리케이션 OAuth 클라이언트 ID | **EAS 환경 변수(Environment)에 넣는다.** 비어 있으면 구글 버튼이 "설정 안내" 오류를 내고 나머지 기능은 정상 | `.env`에 적는다 |

로컬 개발용 `.env`는 예시 파일을 복사해 만든다. `.env`는 git에서 제외된다.

```bash
cp .env.example .env          # PowerShell: Copy-Item .env.example .env
```

### 2-3. EAS 빌드 프로필 (`eas.json`)

| 프로필 | 산출물 | 배포 | API 주소 | 개발용 로그인 | 용도 |
| --- | --- | --- | --- | --- | --- |
| `development` | 개발 클라이언트 | internal | `https://j15D105.p.ssafy.io/api` | 켬 | `expo-dev-client`로 개발 중 네이티브 기능 확인 |
| `preview` | **APK** | internal | 같음 | 켬 | **QA·시연용. 기본으로 이 프로필을 쓴다** |
| `production` | APK | — | 같음 | 끔 | 최종 배포. `versionCode` 자동 증가 |

`appVersionSource`가 `remote`라서 `versionCode`는 EAS 서버가 관리한다. `app.json`의 `version`(1.0.0)만 저장소에서 바꾼다.

## 3. EAS Build로 APK 만들기 (권장)

### 3-1. 로그인과 프로젝트 확인

```bash
npx eas-cli@latest login
npx eas-cli@latest whoami
```

`app.json`의 `extra.eas.projectId`(`83d2404b-…`)가 `d105-dodam` 조직의 `dodam` 프로젝트에 연결되어 있다. 조직에 속하지 않은 계정으로 빌드하면 권한 오류가 난다.

### 3-2. EAS 환경 변수 확인

구글 로그인이 필요하면 빌드 전에 EAS 환경 변수에 `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`가 있어야 한다. 프로필별 `environment` 이름(`development`, `preview`, `production`)에 맞춰 넣는다.

```bash
# 현재 값 확인
npx eas-cli@latest env:list --environment preview

# 없으면 추가 (값은 팀 내부 채널에서 받는다)
npx eas-cli@latest env:create --environment preview \
  --name EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID --value "<웹 클라이언트 ID>" --visibility plaintext
```

Expo Dashboard의 프로젝트 → Environment variables 메뉴에서도 같은 작업을 할 수 있다.

### 3-3. 빌드 실행

```bash
npx eas-cli@latest build --platform android --profile preview --message "최종 QA APK"
```

- 처음 빌드하는 계정이라면 키스토어를 묻는다. **"Generate a new Android Keystore"를 고르지 말고** 기존 EAS 관리 키스토어를 그대로 쓴다. 키스토어가 바뀌면 SHA-1이 달라져 구글 로그인이 깨지고, 기존 설치본 위에 덮어 설치가 안 된다.
- 소요 시간은 큐 대기를 포함해 보통 10~20분이다.
- 끝나면 터미널에 Build details 링크와 APK 다운로드 링크가 나온다.

`production` 프로필은 `--profile production`으로 바꿔 실행한다. 개발용 로그인이 숨겨지므로 구글 로그인 설정이 완료된 상태에서만 쓴다.

### 3-4. 산출물 받기

| 방법 | 절차 |
| --- | --- |
| 터미널 | 빌드 완료 후 출력되는 APK 링크를 기기 브라우저에서 연다 |
| Expo Dashboard | expo.dev → `d105-dodam` → `dodam` → Builds → 해당 빌드 → **Install** (QR 코드) 또는 **Download** |
| CLI | `npx eas-cli@latest build:list --platform android --limit 5`로 빌드 ID를 확인한 뒤 `npx eas-cli@latest build:download --id <빌드 ID>` |

### 3-5. 빌드 상태 확인

```bash
npx eas-cli@latest build:list --platform android --limit 5
npx eas-cli@latest build:view <빌드 ID>
```

## 4. 로컬에서 APK 만들기 (EAS를 쓸 수 없을 때)

저장소에는 `android/` 폴더가 없다. `prebuild`로 네이티브 프로젝트를 생성한 뒤 Gradle로 빌드한다.
1-2절의 JDK·Android SDK가 설치되어 있어야 한다.

### 4-1. 환경 변수 준비

로컬 빌드는 `eas.json`을 읽지 않으므로 `.env`에 직접 적는다.

```dotenv
EXPO_PUBLIC_API_BASE_URL=https://j15D105.p.ssafy.io/api
EXPO_PUBLIC_ENABLE_DEMO_LOGIN=true
EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=      # 있으면 넣고, 없으면 비워 둔다
```

### 4-2. 네이티브 프로젝트 생성과 빌드

```bash
npx expo prebuild --platform android --clean
cd android
./gradlew assembleRelease        # Windows: .\gradlew.bat assembleRelease
```

산출물: `android/app/build/outputs/apk/release/app-release.apk`

### 4-3. 로컬 빌드의 제약

- **서명이 다르다.** 로컬 빌드는 EAS 키스토어가 아닌 디버그 키스토어(또는 직접 만든 키)로 서명된다. 따라서
  - EAS APK가 설치된 기기에는 덮어 설치가 안 된다. 기존 앱을 지우고 설치한다.
  - 구글 로그인은 Google Cloud Console의 Android OAuth 클라이언트에 이 키스토어의 SHA-1을 추가 등록해야 동작한다. 시연에는 개발용 로그인을 쓰면 된다.
- 직접 키스토어로 서명하려면 `android/app/build.gradle`의 `signingConfigs.release`에 keystore 경로·비밀번호를 넣는다. `*.jks`는 git에서 제외된다.
- `prebuild`가 만든 `android/`는 git에서 제외된다. 설정을 바꿀 때는 `app.json`·`app.config.js`를 고치고 다시 `prebuild --clean` 한다.

### 4-4. 기기에 바로 실행 (개발용)

USB 디버깅을 켠 실기기나 에뮬레이터가 연결된 상태에서:

```bash
npx expo run:android --variant release
```

`prebuild`와 Gradle 빌드, 설치까지 한 번에 한다. 디버그 빌드(`--variant` 생략)는 Metro 서버가 켜져 있어야 실행된다.

## 5. 기기에 설치하고 확인하기

### 5-1. 설치

| 방법 | 절차 |
| --- | --- |
| 기기에서 직접 | 3-4절의 링크를 기기 브라우저로 열어 APK 내려받기 → 파일 열기 → "출처를 알 수 없는 앱 설치 허용" → 설치 |
| PC에서 ADB | `adb install -r dodam.apk` (`-r`은 같은 서명의 기존 앱 위에 덮어쓰기) |

같은 서명의 앱이 이미 있으면 덮어 설치되고 로그인 상태(SecureStore)가 유지된다. 서명이 다르면 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`이 나므로 기존 앱을 먼저 삭제한다.

### 5-2. 설치 후 확인 체크리스트

| 순서 | 확인 | 기대 결과 |
| --- | --- | --- |
| 1 | 앱 실행 | 흰 배경 스플래시 → 로그인 화면. 정적 로고가 깜빡이지 않는다 |
| 2 | 로그인 화면 하단 | `preview`면 "개발용 로그인" 영역이 보이고, `production`이면 안 보인다 |
| 3 | 개발용 로그인 | 시연 계정(값은 [시연시나리오.md](시연시나리오.md))으로 로그인 → 홈 이동. 실패하면 서버 주소나 서버 상태를 확인한다 (`https://j15D105.p.ssafy.io/api/health`) |
| 4 | 구글 로그인 버튼 | 계정 선택 창이 뜬다. "설정 안내" 오류가 뜨면 `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`가 빌드에 안 들어간 것 |
| 5 | 알림 권한 | 첫 진입 시 권한 요청이 뜬다. 허용 후 서버에 FCM 토큰이 등록된다 |
| 6 | 하단 탭 | 홈 · 가계부 · 토리 · 자산 · 발견 다섯 탭이 전환된다 |

빌드된 APK의 정보는 `aapt`로 확인할 수 있다.

```bash
aapt dump badging dodam.apk | grep -E "package|sdkVersion|application-label"
```

## 6. 트러블슈팅

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 빌드 로그에 `splashscreen_logo not found` | `expo-splash-screen`이 참조하는 Android drawable이 없음 | `assets/splash/transparent_splash.xml`이 있고 `app.json`의 `android.drawable.icon`이 그 경로를 가리키는지 확인 |
| 빌드 로그에 `google-services.json` 관련 오류 | 파일이 없거나 패키지명이 다름 | `frontend/google-services.json`의 `package_name`이 `com.ssafy.d105.dodam`인지 확인. EAS에서 파일을 비밀값으로 주입하려면 `GOOGLE_SERVICES_JSON` 환경 변수(file 타입)에 경로를 넣는다 |
| 구글 버튼이 "설정 안내" 오류 | `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`가 빌드 시점에 비어 있어 네이티브 플러그인이 빠짐 | 3-2절대로 EAS 환경 변수를 넣고 **다시 빌드**한다. 환경 변수는 빌드 시점에만 반영된다 |
| 구글 로그인에서 `DEVELOPER_ERROR` | Android OAuth 클라이언트에 등록된 SHA-1과 APK 서명이 다름 | `npx eas-cli@latest credentials -p android`로 EAS 키스토어의 SHA-1을 확인해 Google Cloud Console에 등록. 로컬 빌드면 그 키스토어의 SHA-1을 추가한다 |
| 로그인 후 "환경 변수가 설정되지 않았습니다" | `EXPO_PUBLIC_API_BASE_URL` 누락 (로컬 빌드에서 `.env`를 안 만든 경우) | 4-1절의 `.env`를 만들고 다시 빌드 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 설치된 앱과 서명이 다름 | 기존 앱 삭제 후 설치 |
| EAS 빌드 권한 오류 (`not authorized`) | `d105-dodam` 조직 밖 계정 | 조직에 초대받거나 팀 계정으로 `eas login` |
| Metro 번들 단계에서 TypeScript·ESLint 오류 | 코드 문제 | 빌드 전에 `npm run lint -- --no-cache`, `npx tsc --noEmit` 통과 확인 |
| 로컬 Gradle 빌드에서 메모리 부족 | 기본 힙 2 GB | `android/gradle.properties`의 `org.gradle.jvmargs`를 `-Xmx4096m`으로 올린다 |
| 에뮬레이터가 `offline` | ADB 연결 문제 | Android Studio Device Manager에서 Cold Boot, 그래도 안 되면 `adb kill-server && adb start-server` |
