# 목표 통장 이체 — FE 작업 계획

작성일: 2026-09-23. 대상: FE 담당.
BE 계획: [backend/docs/goal-transfer-plan.md](../backend/docs/goal-transfer-plan.md)

> **이 문서는 [safebox-frontend-request.md](safebox-frontend-request.md)를 대체합니다.** 그 문서의
> "입출금은 목표에 연결할 수 없다", "담기 화면은 만들지 않는다"는 아래 내용으로 뒤집혔습니다.

---

## 0. 한 줄 요약

목표에 모으는 돈을 **목표 전용 통장으로 실제 이체**합니다. 그 통장 잔액이 곧 목표에 모인 금액입니다.
SSAFY 금융망 이체 API로 **진짜 돈이 움직입니다.**

FE가 만들 것은 **보내기 / 되가져오기 두 방향의 이체 화면**입니다. 지난번에 요청드린 계좌 필터 수정은
**철회**합니다(§6).

---

## 1. 왜 바뀌었나 (배경)

목표의 "모인 금액"을 어떻게 셀지가 문제였습니다. 입출금 통장을 목표에 연결하면 잔액 전체가 모인 돈이 되어,
시연 계정에서 주거래 통장 1,746만원이 통째로 잡혀 진행률이 98%로 보였습니다.

| 검토안 | 결과 |
| --- | --- |
| 잔액 전액 반영 | 진행률 98% 문제 |
| 예·적금만 반영 | 적금 없이 통장에 모으는 사용자가 진행률 0%로 안 보임 |
| 세이프박스(가상 담기) | 실제 이체가 안 되니 "담아둔 돈"이 언제든 거짓이 됨. **중단** |
| 목표 생성 시점 기준선 | 동작하지만 잔액 출렁임·목표 간 안분 등 보정이 계속 필요 |
| **목표 통장 이체** | **채택.** 통장 잔액이 곧 목표 돈이라 모호함이 없음 |

**계산식은 하나도 바뀌지 않습니다.** BE가 이체 API를 추가하고, 지난번에 좁혔던 계좌 연결 제약을 되돌립니다.

## 2. 필요한 UI

### 2-1. 진입점 — 목표 상세

[GoalDetailScreen](../frontend/src/pages/goalDetail/GoalDetailScreen.tsx)의 연결 계좌 영역입니다.
`data.linkedAccounts` 중 `accountType === 'DEMAND_DEPOSIT'`인 것이 목표 통장입니다.

| 상태 | 화면 |
| --- | --- |
| 목표 통장 있음 | 그 카드에 **[보내기]** / **[되가져오기]** 두 버튼 |
| 목표 통장 없음 (예·적금만 연결) | "목표 통장을 연결하면 돈을 모을 수 있어요" 안내 + 연결 화면으로 이동 |
| 연결 계좌 자체가 없음 | 기존 빈 상태 유지 |

**목표 통장이 없는 경우가 기본값입니다.** 기존 목표는 예·적금만 연결돼 있거나 아무것도 없습니다.
이 빈 상태를 먼저 만들어 주셔야 진입 경로가 생깁니다.

> ⚠️ **알려진 한계.** 사용자가 목표 전용 통장을 이미 갖고 있지 않으면, 안내를 따라가도 결국 월급통장을
> 연결하게 됩니다. 그러면 그 잔액 전체가 목표에 잡혀 이 작업이 없애려던 문제가 그 사용자에게 재현됩니다.
> **시연 범위 밖이지만 출시 전에는 통장 개설 유도가 필요합니다**(§7-4). §5 안내 문구가 완화책입니다.

기존 `GoalAccountManagementBottomSheet`가 연결 관리를 이미 담당하므로, 이체 시트도 같은 바텀시트 패턴으로
붙이면 됩니다.

### 2-2. 보내기 시트

```
목표 통장에 보내기

  받는 곳   결혼 자금 통장   110000-**-**3002  7,000,000원
  보낼 통장 [ 주거래 입출금  110000-**-**3001 ▾ ]  17,460,000원

  금액      [          500,000 ] 원
            [ 1만 ] [ 5만 ] [ 10만 ] [ 전액 ]

                    [ 보내기 ]
```

- **받는 곳(입금)**: 목표에 연결된 입출금 계좌. 고정 표시
- **보낼 통장(출금)**: `assetApi.getAccounts()`에서 `DEMAND_DEPOSIT`이고 `status !== 'CLOSED'`이며
  받는 곳과 다른 계좌. **선택지가 없으면 시트 대신 안내를 띄웁니다**
- **금액**: 천 단위 구분 표시, 숫자 키패드. 상한은 출금 통장 잔액
- **버튼 비활성 조건**: 금액이 0 이하, 잔액 초과, 출금 계좌 미선택, 전송 중

### 2-3. 되가져오기 시트

**같은 API를 방향만 바꿔 호출합니다.** 출금이 목표 통장, 입금이 사용자가 고른 통장입니다.

- **금액 상한은 목표 통장 잔액**입니다(보내기와 반대)
- **되가져오면 목표 진행률이 내려갑니다.** 확인 단계에서 이를 알려 주세요

이 화면이 설계상 중요합니다. 목표 통장의 돈을 쓰려면 **되가져오기라는 의식적 행동**이 필요하다는 것이
이 방식을 택한 이유입니다. 없으면 사용자가 목표 통장에 돈을 넣고 꺼낼 방법이 없습니다.

### 2-4. 확인 단계 (필수)

**실제 돈이 움직이므로 확인 없이 실행하면 안 됩니다.**

```
결혼 자금 통장으로
500,000원을 보낼까요?

주거래 입출금 → 결혼 자금 통장

        [ 취소 ]  [ 보내기 ]
```

되가져오기는 같은 형태에 **진행률이 내려간다는 경고**를 더합니다.

```
주거래 입출금으로
500,000원을 되가져올까요?

결혼 자금 진행률이 32% → 29%로 내려가요

        [ 취소 ]  [ 되가져오기 ]
```

### 2-5. 전송 중 / 완료 / 실패

| | 화면 |
| --- | --- |
| 전송 중 | 버튼을 스피너로 바꾸고 시트 전체를 비활성화. **최대 15초** 걸릴 수 있습니다(§3-5) |
| 완료 | 보낸 금액과 갱신된 목표 진행률을 보여준 뒤 닫기. 최소한 토스트 + 목표 상세 재조회 |
| 실패 | §3-3 오류표대로 문구 분기. 시트는 열어 두고 금액을 고칠 수 있게 |

## 3. 연동

### 3-1. 어디에 붙이나

| | 위치 |
| --- | --- |
| API 함수 | [frontend/src/api/assetApi.ts](../frontend/src/api/assetApi.ts) — 계좌 도메인입니다 |
| 요청·응답 타입 | 계좌 타입 파일. 기존 `*.types.ts` 패턴을 따릅니다 |
| 출금 계좌 목록 | `assetApi.getAccounts()` — `GoalSetupScreen`이 이미 쓰는 함수입니다 |
| 연결 계좌 | `GET /api/v1/goals/{goalId}/accounts` (목표 상세가 이미 호출) |

### 3-2. 호출

```
POST /api/v1/accounts/transfer
{ "withdrawalAccountId": 11, "depositAccountId": 12, "amount": 500000 }
```

되가져오기는 두 id를 바꿔 넣습니다.

### 3-3. 오류

판별은 기존 패턴을 씁니다 — `isApiError(error) && error.code === '...'`
([ApiError.ts](../frontend/src/api/ApiError.ts), `GoalSetupScreen`에 선례가 있습니다).

| 상황 | HTTP | 코드 | 화면 |
| --- | --- | --- | --- |
| 성공 | 200 | — | 완료 처리 |
| 같은 계좌·0 이하·예적금·해지 계좌 | 400 | `INVALID_REQUEST` | 입력 오류 안내 |
| 타인·없는 계좌 | 404 | `RESOURCE_NOT_FOUND` | 재조회 유도 |
| 금융망 미연결 | 409 | `FINANCE_NOT_CONNECTED` | **`financeDataApi.connect()` 경로로 유도** |
| 잔액 부족 | 409 | `TRANSFER_INSUFFICIENT_BALANCE` | 금액 조정 안내 |
| 이체 한도 초과 | 409 | `TRANSFER_LIMIT_EXCEEDED` | 한도는 **계좌마다 다릅니다.** 문구에 고정 금액을 쓰지 마세요 |
| 금융망이 오류 응답 | 502 | `FINANCE_API_ERROR` | 재시도 안내 |
| 금융망에 닿지 못함 | 503 | `FINANCE_API_UNAVAILABLE` | 재시도 안내 |

### 3-4. ⚠️ 중복 전송 방어는 FE가 1차입니다

**두 번 누르면 두 번 이체됩니다.** 전송 중 버튼을 비활성화하고 응답 전까지 재요청을 막아 주세요.
`GoalDetailScreen`의 `isSavingAccountsRef` 같은 ref 가드 패턴이 이미 있습니다.

BE도 짧은 시간 내 동일 요청을 거절하지만 그건 2차 방어입니다.

### 3-5. 그 밖에

- **낙관적 업데이트를 하지 마세요.** 실제 이체라 실패할 수 있습니다. 응답을 받은 뒤에만 화면을 바꿉니다.
- **타임아웃**: `apiClient` 기본값이 15초입니다. 외부 금융망 호출이라 기본값으로 두되, 리허설에서 실제
  응답 시간을 재고 부족하면 `timeoutMs`로 늘립니다.
- **재조회 범위**: 목표 상세뿐 아니라 **자산·계좌 화면의 잔액도 바뀝니다.** 그 화면으로 돌아갈 때
  최신 값이 보이도록 캐시를 다루어 주세요.
- **응답 본문**은 갱신된 두 계좌 잔액입니다 — `withdrawalBalance`, `depositBalance`, `transferredAmount`.
  목표 진행률은 담기지 않으므로 **목표 상세는 따로 재조회**해야 합니다.

## 4. 시연에서 보이는 값 (9/27)

> 결혼 자금 목표 상세 → "보내기" → 50만원 → 확인

| 화면 값 | 이체 직후 |
| --- | --- |
| 모인 금액 | **상승** |
| 진행률 | **상승** |
| 예상 달성일 | **당겨짐** (남은 금액이 줄어서) |
| 저축속도 | **변화 없음** |

**저축속도는 움직이지 않습니다.** "이번 달을 뺀 직전 3개 완료 월"을 기준으로 계산되어 당월 이체는 다음 달부터
반영됩니다. **발표 멘트에서 "저축 속도가 올라갑니다"는 빼야 합니다.**

시연 계정은 BE가 리허설 전에 준비합니다. 기존 주거래 통장 연결을 해제하고 목표 통장을 연결하므로,
**준비 직후 진행률이 지금보다 크게 떨어져 있는 것이 정상입니다.**

시작 진행률과 이체 금액은 **화면에서 막대가 눈에 띄게 움직이도록** 리허설에서 함께 조정합니다.
목표 통장을 0원에서 시작하면 한 번 이체해도 진행률이 거의 안 움직여 시연이 약해집니다.
리허설 때 같이 보면서 정하죠.

## 5. 권장 — 연결 시 안내

목표에 연결할 통장을 고를 때 띄우면 좋겠습니다. 급여통장을 고르면 생활비가 드나들어 모은 금액이 출렁입니다.

```
💡 목표용 통장을 따로 두면 더 정확해요

   급여통장은 생활비가 드나들어 모은 금액이 오르내려요.
   목표 통장은 넣은 만큼 그대로 쌓입니다.
```

## 6. 하지 않아도 되는 것

[safebox-frontend-request.md](safebox-frontend-request.md)에서 요청드린 **계좌 선택 필터 수정 2건은 철회합니다.**

- `GoalSetupScreen`의 계좌 필터
- `useGoalDetail`의 계좌 필터

BE가 `PUT /goals/{goalId}/accounts`의 예·적금 한정을 해제하므로 목표 만들기·목표 상세가 원래대로 동작합니다.
**이미 수정에 착수하셨다면 알려주세요.**

`PUT /goals/{goalId}/allocations/{accountId}`(담기)는 제거됩니다. 쓰지 마세요.

## 7. 미정 항목

| | 내용 | 상태 |
| --- | --- | --- |
| 1 | 이체 API 응답 본문 | **확정.** 갱신된 두 계좌 잔액을 돌려줍니다(`withdrawalBalance`, `depositBalance`, `transferredAmount`). 목표 진행률은 담기지 않으므로 **목표 상세는 재조회**하세요 |
| 2 | 목표에 입출금이 여러 개일 때 받는 곳 | **확정 — 목표당 목표 통장은 1개입니다.** BE가 2개 이상 연결을 400으로 막습니다. 받는 곳은 항상 하나이므로 **고정 표시**하면 됩니다 |
| 3 | 이체가 목표 이력에 남는지 | **해결.** 이체 후 목표 상세를 조회하면 `AMOUNT_UPDATED`가 기록되어 차트에 반영됩니다 |
| 4 | 일반 사용자의 목표 통장 확보 경로 | **시연 범위 밖.** 제품에서는 통장 개설 안내가 필요합니다 |
| 5 | 금융망 미연결 사용자의 연동 경로 | **해결.** `financeDataApi.connect()`가 이미 있습니다 |

| | 담당 | 규모 |
| --- | --- | --- |
| 금융망 어댑터, 이체 API, 계좌 연결 제약 해제, 시연 데이터 | BE | 1.5~2일 |
| **이체 화면** | **FE** | **여력 확인 필요** |

화면이 어렵다면 시연에서 이체를 빼고 진행합니다. 그 경우 **FE 작업은 0이 됩니다**(§6의 회귀 해소가
BE 쪽에서 일어나므로). 시연은 목표 통장 없이 예·적금 기준 진행률로 갑니다.

**9/25까지 답을 주셔야 합니다.** 그 이후에 시작하면 리허설 시간이 남지 않습니다.

축소가 필요하면 이 순서로 자르는 것을 권합니다 — ①빠른 금액 버튼 ②완료 화면(토스트로 대체)
③되가져오기.

**확인 다이얼로그와 중복 방어는 자르면 안 됩니다.** 실제 돈이 움직입니다.

③을 자르는 것은 **시연 한정**입니다. 되가져오기가 없으면 사용자가 목표 통장에 넣은 돈을 도담에서
뺄 수 없으므로, 출시 전에는 반드시 있어야 합니다(§2-3).
