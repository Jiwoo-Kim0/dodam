# 월간 리포트 FE 화면 기준 API 협의안

기준 화면: `frontend/src/pages/report/ReportScreen.tsx` 및 `frontend/src/types/report.types.ts`.
현재 화면은 이미 프론트에서 구성되어 있으며, API 20 구현 전까지 거래·소비·자산·현금흐름 API를 조합한 **참고값**을 표시한다. 이 문서는 [백엔드의 API 20 선공유 계약](../backend/docs/improvement-report-contract.md)을 대체하는 확정 명세가 아니라, 화면을 실제 리포트 데이터로 연결하기 위한 추가 협의 요청이다.

## 백엔드에 요청할 내용

1. `GET /api/v1/reports/monthly?yearMonth=YYYY-MM`의 기준 월은 직전 완료 월을 기본값으로 유지한다. 응답에는 `period`, `generatedAt`, 데이터 부족/미생성 상태를 구분할 수 있는 사유를 포함한다. `0원`과 `계산 불가(null)`를 구분한다.
2. 현재 월간 응답의 `totalIncome`, `totalExpense`, `totalSaving`, 전월 비교 외에 화면이 필요한 아래 항목을 API 20의 하위 응답 또는 명시적인 별도 엔드포인트로 제공할 수 있는지 협의한다. FE에서 화면 모양에 맞춰 값을 임의로 추정하지 않도록 **계산 기준과 기준 기간**도 함께 고정해 달라.

| 화면 카드 | 필요한 서버 데이터 | 현재 FE 임시 처리 및 주의점 |
| --- | --- | --- |
| 금융 효율 점수 | `score`, `maxScore`, `previousMonthDifference`, `summary`, `calculationVersion`; 상대 순위는 실제 비교 모집단이 있을 때만 `percentile` | 저축률·고정비 비율·현재 현금흐름 위험으로 만든 참고 점수다. 현재 위험을 과거 점수에 적용하거나 점수에서 순위를 역산하지 않는다. |
| 금융 생활 패턴 | `status`, `title`, `description`, `evidencePeriod`가 있는 패턴 목록 | 현재는 저축률·이상 소비·현금흐름 위험 API를 FE가 조합한다. 데이터 없음과 위험 없음은 구분해야 한다. AI 코치 문구는 기존 API 21 별도 호출 계약을 유지한다. |
| 다음 달 예상 지출 | `forecastMonth`, `expectedExpense`, `differenceFromBaseMonth`, 중복되지 않는 `breakdown[]`, `basis`, `generatedAt` | 현재 고정·변동지출의 지난달 월평균을 합친 참고치다. 카드 사용액은 이미 포함되어 있으므로 다시 합산하지 않는다. 예정 결제액과 예측 지출을 섞는다면 중복 제거 규칙이 필요하다. |
| 주요 지표 | 저축률, 고정지출 비중, 카드 사용액, 대출 잔액 및 각각의 전월 비교 가능 여부 | 기존 개별 API로 계산 중이다. 대출은 자산 총액에서 제외하되 이 카드의 별도 지표로는 유지한다. |
| 지난 소비 | 기준 월까지 최근 6개월의 `yearMonth`, `amount` (빠진 달은 0원 또는 미계산 사유 명시) | 기존 카테고리 추이 API를 사용 중이다. 화면의 평균선은 받은 6개월 값을 FE가 계산할 수 있다. |

3. FE가 사용할 상태를 구분해 달라: 리포트 미생성(생성 대기/데이터 부족), 정상 생성됐지만 거래 0건, 일부 지표 계산 불가, 일시적 서버 오류. 현재 계약의 404 하나로 모두 표현하면 사용자 안내를 정확히 나누기 어렵다.
4. 월 선택 UI는 현재 표시만 되고 동작하지 않는다. 과거 월 조회 가능 범위, 미생성 월 처리, 재생성·캐시 정책을 확정하면 선택 동작을 연결할 예정이다.

## 데일리 브리핑 관련 확인

현재 FE는 전날 소비 합계·거래 목록과 지난달 일평균 카테고리 소비를 비교하여 브리핑 상세를 구성한다. 따라서 카드 문구는 **통계 비교**이며 AI가 작성한 분석 문장은 아니다. API 20의 `DailyReport.coachMessage`가 당분간 `null`인 현재 계약과 일치한다. 향후 화면의 “어제 소비가 목표 달성일을 며칠 바꿨다” 또는 “배달 없는 날”처럼 인과관계·세부 분류가 필요한 문구를 원한다면, 출처와 계산 근거가 있는 전용 응답이 필요하다. 확인되지 않은 값은 FE에서 만들어 표시하지 않는다.

## FE 전환 기준

- API 20 구현 및 명세 갱신 후 DTO·응답 샘플을 공유받는다.
- 필드별 출처·기간·null/0 규칙이 확정되면 `useReportData`의 임시 집계를 서버 응답 매핑으로 교체한다.
- 합계 일치, 월 경계(Asia/Seoul), 중복 지출, 빈 결과·오류, 새로고침과 화면 재진입을 통합 테스트한다.
