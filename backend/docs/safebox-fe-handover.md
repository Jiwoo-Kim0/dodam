# FE 인계 — 목표 담기·꺼내기(세이프박스) 화면 계약

> ⛔ **폐기(2026-09-23).** 세이프박스(가상 담기)를 접고 금융망 실제 이체로 방향을 바꿨습니다.
> 이 문서의 담기 화면 요청은 무효이며 [../../docs/goal-transfer-plan.md](../../docs/goal-transfer-plan.md)가
> 대신합니다. 중단 근거는 [safebox-allocation-plan.md](safebox-allocation-plan.md) 상단에 있습니다.

작성일: 2026-09-23. 대상: FE 담당(114). BE 이슈: S15P21D105-703 MR-B.

**이 문서는 "가능한지" 판단을 받기 위한 것입니다.** BE 구현은 하루면 되지만 화면이 없으면 사용자에게 기능이 보이지 않습니다.
9/27 발표 리허설까지 FE 여력이 있는지 먼저 알려 주시면, 그 답에 따라 BE 착수 여부를 정하겠습니다.

---

## 1. 무엇을 만드는가

통장 잔액 중 일부를 목표에 **"담아 두는"** 기능입니다. 카카오뱅크 세이프박스와 같은 개념이되, 실제 은행 이체는 없고
도담 안에서만 구분합니다.

```
주거래 통장 잔액 1,000,000원
  ├─ 결혼 자금에 담김      300,000원
  ├─ 여행 자금에 담김      200,000원
  └─ 아직 안 담음          500,000원   ← 더 담을 수 있는 금액
```

담은 금액만 그 목표의 "모인 금액"이 됩니다. 꺼내면 줄어듭니다.

### 지금과 무엇이 달라지나

현재는 입출금 계좌를 목표에 연결하면 **잔액 전체**가 그 목표의 모인 금액이 됩니다. 시연 계정에서 주거래 통장
1,746만원이 통째로 '결혼 자금'으로 잡혀 진행률이 98%로 보이는 것이 이 때문입니다. 담기가 생기면 사용자가 지정한
금액만 잡힙니다.

**예·적금은 달라지지 않습니다.** 지금처럼 계좌 하나를 목표 하나에 전액 연결합니다.

## 2. API 계약

### 2-1. 담기·꺼내기 (신규)

```
PUT /api/v1/goals/{goalId}/allocations/{accountId}
Body: { "amount": 300000 }
```

- **절대값입니다.** 증감이 아니라 "이 목표에 이 계좌에서 담아 둘 금액"을 그대로 보냅니다.
  담기도 꺼내기도 같은 호출이고, 더 작은 값을 보내면 꺼내기입니다.
- `amount: 0`이면 할당을 완전히 해제합니다.
- 같은 요청을 여러 번 보내도 결과가 같습니다(멱등). **중복 탭·재시도 방어를 FE가 따로 하지 않아도 됩니다.**
- 대상은 자유입출금 계좌만입니다. 예·적금을 보내면 400입니다.
- A 목표 → B 목표 직접 이동은 없습니다. 필요하면 A에서 꺼내고 B에 담는 두 번의 호출로 합니다.

응답은 갱신된 목표 연결계좌 정보입니다(2-2와 같은 형태).

### 2-2. 화면을 구성할 데이터 (이미 있음)

```
GET /api/v1/goals/{goalId}/accounts?page&size
```

**이 응답만으로 담기 화면을 만들 수 있습니다.** 별도의 "담을 수 있는 금액" 조회 API는 두지 않습니다.
아래 필드는 626에서 이미 내려가고 있으니 지금 확인해 보실 수 있습니다.

| 필드 | 의미 | 화면에서 |
| --- | --- | --- |
| `balance` | 실제 계좌 잔액 | "통장 잔액" |
| `allocatedToThisGoal` | 이 목표에 담긴 금액 | 슬라이더·입력값의 현재치 |
| `allocatedElsewhere` | 다른 목표에 담긴 금액 | "다른 목표에 200,000원" |
| `availableToAllocate` | `max(0, balance − 전체 담긴 금액)` | **입력 상한** |
| `shortfallAmount` | `max(0, 전체 담긴 금액 − 잔액)` | 부족 경고 금액 |
| `allocationStatus` | `OK` \| `NEEDS_ADJUSTMENT` | 부족 상태 배지 |
| `contributionAmount` | 저장 원문(null 가능) | 보통 안 씁니다 |

입력 상한은 `allocatedToThisGoal + availableToAllocate`입니다. 즉 이미 담은 금액은 그대로 두고 남은 여유분까지
올릴 수 있습니다.

### 2-3. 기존 API 변경 (주의)

```
PUT /api/v1/goals/{goalId}/accounts   Body: { "accountIds": [...] }
```

**예·적금 전용으로 좁힙니다.** 지금은 입출금도 받지만, MR-B 이후 입출금 id를 보내면 400이 나고 담기 API를 쓰라는
안내가 옵니다.

- 빈 배열은 **예·적금 연결만** 해제합니다. 입출금 담은 금액은 그대로 남습니다.
- 목표 화면에서 계좌를 고르는 UI가 지금 입출금까지 함께 보낸다면 분기가 필요합니다.

## 3. 오류

| 상황 | HTTP | 코드 |
| --- | --- | --- |
| 미인증 | 401 | — |
| 타인·없는·삭제된 목표/계좌 | 404 | `RESOURCE_NOT_FOUND` |
| 예·적금 계좌, 줄이기 목표, 음수·소수·null | 400 | `INVALID_REQUEST` |
| 종료된 목표(ACHIEVED·CANCELED)에 **더 담기** | 409 | `GOAL_NOT_EDITABLE` |
| 담을 수 있는 금액 초과 | 409 | `GOAL_ALLOCATION_EXCEEDS_AVAILABLE` (신규) |

- **꺼내기는 종료된 목표에서도 됩니다.** 담기(증가)만 막습니다.
- 부족 상태(`NEEDS_ADJUSTMENT`)에서는 추가 담기가 409이고 꺼내기는 허용됩니다.

## 4. 화면 제안

BE 계약만 지키면 형태는 자유입니다. 참고용입니다.

### 4-1. 담기 시트

목표 상세의 `연결 계좌` 관리에서 입출금 계좌를 누르면 뜨는 바텀시트를 생각했습니다.

```
주거래 입출금  110000-**-**3001

  통장 잔액            17,460,000원
  다른 목표에 담김        200,000원
  이 목표에 담긴 금액   [  500,000  ]원
  ───────────────────────────────
  더 담을 수 있는 금액  16,760,000원

              [ 담기 ]
```

입력값을 그대로 `amount`로 보내면 됩니다.

### 4-2. 부족 상태

`allocationStatus == "NEEDS_ADJUSTMENT"`이면 담아둔 돈에 실제로 손을 댄 상태입니다. 진행률이 실제보다 높게
보이므로 함께 표시해 주세요.

> 담아둔 돈 중 80,000원이 통장에서 빠져나갔어요. 조정이 필요해요.

### 4-3. (선택) 꺼낼 때 목표 영향

BE에 이미 있는 `POST /api/v1/simulations/saving`으로 "꺼내면 며칠 늦어지는지"를 보여줄 수 있습니다.
**MR-B 범위 밖이고 후순위입니다.** 여력이 없으면 빼셔도 나머지는 성립합니다.

## 5. 시연 시나리오

FE가 가능하다고 하면 이 흐름을 생각하고 있습니다.

1. 목표 '내 집 마련 준비' — 적금 3개가 연결돼 있고 진행률 30%
2. 발견 화면에서 "통장에 매달 32만원이 남고 있어요"
3. 목표 상세 → 주거래 통장 담기 → **진행률과 예상 달성일이 바로 움직임**
4. (선택) 꺼내기를 눌러 "43일 늦어져요" 확인

**3번이 이 시연의 핵심 장면입니다.** 지금은 보여줄 수 있는 인터랙션이 없습니다.

선행 조건으로 시연 서버에 678 seed를 적용해야 합니다(BE·데이터 담당). 적용 전에는 목표에 입출금이 이미 연결돼
있어서 담기를 하면 진행률이 **내려갑니다**.
