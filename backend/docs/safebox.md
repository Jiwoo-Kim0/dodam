# 도담 전용 계좌와 목표별 세이프박스 (S15P21D105-705)

사용자에게 SSAFY 금융망 입출금 계좌를 **하나** 개설하고 `safebox_account`로 지정한다. 기존 계좌와 이 계좌 사이의 돈 이동만 실제 금융망 이체다. 목표에 담기·꺼내기는 `goal_account.contribution_amount`를 바꾸는 내부 배정이며 금융망 거래를 만들지 않는다. 여러 모으기 목표가 같은 전용 계좌를 참조한다.

## API

모든 경로는 인증이 필요하며 본인 계좌·목표만 처리한다. 응답은 기존 `ApiResponse`를 사용하고 계좌번호는 마스킹 값만 돌려준다.

| 경로 | 동작 |
| --- | --- |
| `POST /api/v1/safebox/account` | 금융망 연결이 있는 사용자에게 전용 입출금 계좌 1개를 개설한다. 이미 있으면 같은 계좌를 반환한다. 금융망의 사용 가능한 입출금 상품 중 상품 고유번호가 가장 작은 것을 선택한다. |
| `GET /api/v1/safebox/account` | 전용 계좌 ID, 마스킹 번호, 실제 잔액, 목표 배정 합계, 가용액, 부족액을 조회한다. 미개설은 404 `SAFEBOX_ACCOUNT_NOT_FOUND`. |
| `GET /api/v1/safebox/goals/{goalId}` | 해당 모으기 목표의 배정액과 전용 계좌 가용액을 조회한다. 타인·없는 목표는 404. |
| `PUT /api/v1/safebox/goals/{goalId}` | `{ "amount": 300000 }` 절대값으로 담기·꺼내기. 0은 배정액 0으로 유지한다. 재요청으로 금액이 같으면 이동 이력을 추가하지 않는다. |

`PUT`은 원 단위 0 이상 정수만 받는다. 배정액을 늘릴 때는 `계좌 잔액 − 다른 목표 배정액`을 넘을 수 없으며 초과 시 409 `SAFEBOX_ALLOCATION_EXCEEDS_BALANCE`다. 잔액이 배정 합계보다 작아진 상태에서도 감소·0은 허용한다. 종료 목표는 증가만 409 `GOAL_NOT_EDITABLE`로 막는다. 배정 변경과 목표 확보액·이력·`safebox_movement` 기록을 한 DB 트랜잭션에 넣는다. 사용자 행 잠금으로 같은 사용자의 배정을 직렬화한다.

`POST /api/v1/accounts/transfer`는 기존 계좌와 전용 계좌 간 실제 이체에 그대로 사용한다. 전용 계좌에서 출금할 때는 `잔액 − 목표 배정 합계` 이내만 허용하며 초과하면 409 `SAFEBOX_ALLOCATED_BALANCE`다. 마이너스통장 상환·이자 납부의 출금계좌로는 전용 계좌를 사용할 수 없다. 이체 실패·중복 방지·거래 기록은 [account-transfer.md](account-transfer.md) 계약을 따른다.

## 계산과 데이터

`goal_account.contribution_amount`가 목표별 확보액이다. 예·적금은 종전처럼 잔액 전액을 계산한다. 전용 계좌의 입금 자체는 어느 목표에도 귀속하지 않는다. 전용 계좌 목표의 저축속도는 직전 3개 완료 월의 `safebox_movement.delta` 합계를 3으로 나눈 값이다. 당월 담기는 확보액과 진행률에 즉시 반영되지만 완료 월 저축속도는 바꾸지 않는다.

V45는 사용자당 전용 계좌 1개를 강제하는 `safebox_account`와 목표별 이동 원장 `safebox_movement`를 추가한다. 기존 입출금 계좌 연결의 `contribution_amount = NULL`은 **잔액 전액**이라는 계약을 유지한다. 이를 자동으로 숫자 배정으로 전환하면 이미 연결된 목표의 진행률을 임의로 바꾸므로 자동 데이터 마이그레이션은 하지 않는다. 기존 목표의 입출금 연결을 새 전용 계좌 배정으로 옮길 때는 시연·운영 데이터별 연결 및 금액 확인이 필요하다. 기존 연결계좌 PUT은 전용 계좌 배정 링크를 보존하며, 전용 계좌 개설 후 새로운 일반 입출금 계좌 연결은 거절한다.
기존 일반 입출금 연결이 남은 목표에는 세이프박스 배정을 409 `SAFEBOX_LEGACY_LINK_CONFLICT`로 거절한다. 해당 연결을 해제한 뒤 담아야 동일한 잔액을 중복 계산하지 않는다.

## 현재 제한과 FE 연동

- 계좌 개설은 금융망에서 사용 가능한 입출금 상품이 있어야 한다. 금융망 호출 전에 `safebox_open_attempt`를 별도 트랜잭션으로 저장한다. 금융망이 오류 코드로 거절하면(502 `FINANCE_API_ERROR`) 계좌가 생기지 않았으므로 시도 기록을 지우고 재시도를 허용한다. 타임아웃처럼 개설 결과가 불명확하거나 DB 저장에 실패하면 재호출은 409 `SAFEBOX_OPEN_RECONCILIATION_REQUIRED`로 막는다. 생성 응답은 은행 코드와 계좌번호만 주고 `currency`가 객체이므로 이 둘만 읽는다. 은행명·계좌명은 고른 상품의 `bankName`·`accountTypeName`으로, 잔액은 0으로 등록하며 이후 계좌 동기화가 금융망 목록 값으로 갱신한다. 운영자가 금융망 계좌 목록과 DB를 대조해 전용 계좌를 등록하거나, 계좌가 생성되지 않은 사실을 확인한 뒤 시도 기록을 해제해야 한다. 실제 금융망 개설·MySQL V45 제약은 아직 실측 전이다.
- 출금·배정·계좌 동기화는 사용자 DB 행 잠금으로 직렬화한다. 금융망 호출 중에도 DB 트랜잭션을 유지하므로 호출 지연 시 같은 사용자의 작업이 대기한다. 외부에서 금융망 계좌를 직접 출금하면 도담은 이를 사전에 차단할 수 없다. 동기화 후 잔액이 배정 합계보다 작아지면 가용액은 0으로 보여 주며 데이터 대조가 필요하다.
- 가입(이메일·소셜)과 금융망 재연결(`POST /api/v1/finance-data/connection`)이 CONNECTED로 커밋되면 `FinanceConnectedEvent`를 발행하고, `SafeboxOpenListener`가 같은 요청 안에서 전용 계좌를 연다. 금융망 장애가 가입을 막지 않는다는 기존 정책을 지키기 위해 개설 실패는 로그만 남기고 가입·연결 응답은 성공으로 둔다. 이메일이 없어 금융망에 연결하지 못한 소셜 가입은 개설하지 않는다. 가입 응답 시간에 금융망 호출 2회(상품 목록·계좌 생성)가 더해진다.
- FE 708 작업 트리에서는 새 목표 생성 시 기존 계좌 선택을 생략하고 `POST /safebox/account`(있으면 기존 계좌 반환)로 가입 때 빠진 전용 계좌를 보충한 뒤 목표를 만든다. 목표 상세에서는 도담 계좌 이체와 목표별 담기·꺼내기를 구분한다. FE 708과 BE 705를 함께 반영해야 한다.
- 일반 입출금 연결을 사용하는 기존 목표는 하위 호환으로 조회·변경할 수 있다. 사용자가 전용 계좌를 개설한 뒤 새 목표를 연결할 때는 세이프박스 API를 사용해야 한다.

## 시연 계정 준비

무대 흐름은 **목표 생성 → 주거래 → 도담 계좌 실제 이체 → 목표에 담기**다. 금융망 이체(2.4.10)는 두 계좌가 모두 금융망에 있어야 한다.

**자동(배포만 하면 된다).** `SafeboxDemoBootstrap`이 기동 직후 `app.demo.bootstrap-user-emails`(prod 기본 U0003)의 계정을 맞춘다.

1. 금융망 연결이 없으면 `FinanceConnectionService.connect`로 연결한다.
2. 도담 전용 계좌를 금융망 실계좌로 연다(이미 있으면 그대로).
3. SEED `주거래 입출금` 계좌번호가 사용자의 금융망 계좌 목록에 없으면, 금융망 계좌를 새로 열어 현재 주거래 잔액만큼 입금하고 주거래 행의 계좌번호·은행만 그 계좌로 바꾼다(goal-transfer-plan.md §5 B안). `account_id`·잔액·거래·`source_type = SEED`는 유지하고, SEED라 동기화가 덮지 않는다.

이미 맞춰진 단계는 건너뛰므로 재기동해도 금융망 계좌가 늘지 않는다. 실패는 `Demo safebox bootstrap failed` 경고 로그만 남기고 기동은 계속된다. 확인: 기동 로그의 `Demo safebox bootstrap ready for user`, 앱에서 U0003 자산 목록에 도담 계좌가 보이고 주거래 마스킹 번호가 금융망 계좌로 바뀐다.

**목표 생성 = 세이프박스 생성.** 모으기 목표를 만들면 `GoalService`가 도담 계좌에 0원 세이프박스 칸(`goal_account.contribution_amount = 0`)을 함께 만든다. 도담 계좌가 없는 사용자는 FE가 먼저 `POST /api/v1/safebox/account`로 연다.

**수동(선택).** 카카오뱅크·신한 입출금을 보이려면 seed 19(`DODAM_DEMO_U0003_EXTRA_DEMAND_705_SEED.sql`)를 **배포 전에** 적재한다. 주거래 잔액을 15,460,000으로 낮추므로 기동 시 대응보다 먼저여야 금융망 입금액과 맞는다. 이미 대응된 뒤 적재하면 preflight는 통과하지만 금융망 주거래 잔액(대응 시점 값)과 DB 잔액이 달라진다.

- 금융망 회원 생성이 시드 이메일(`seed.kmeans.u0003@dodam.invalid`)을 거절하면 1단계에서 멈춘다. 경고 로그의 오류 코드를 확인한다.
- 기존 U0003 목표 중 주거래가 `contribution_amount = NULL`(잔액 전액)로 연결된 목표는 세이프박스 대상이 아니며(409 `SAFEBOX_LEGACY_LINK_CONFLICT`) 기존 연결 계좌 화면을 보인다. 709 노트북 결제가 이 연결을 쓰므로 해제하지 않는다. 예·적금만 연결된 목표('내 집 마련 준비')와 새 목표는 세이프박스 카드를 보인다.
- 수동 대체 경로: `backend/scripts/prepare_demo_primary_account.py`(주거래 대응만 수행, 출력 SQL 적용).

새 목표는 0원으로 시작하고, 도담 계좌에 실제 이체한 뒤 `PUT /api/v1/safebox/goals/{goalId}`로 원하는 금액을 담는다. 도담 계좌 잔액 전액을 목표에 자동 귀속하지 않는다. 노트북 결제 시연 API(709)는 아직 이 배분 구조와 연결하지 않았다.
