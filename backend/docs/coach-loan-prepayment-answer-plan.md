# 토리 대출 추가상환 답변 개선 계획

## 목표와 범위

사용자가 추가상환을 물으면 **얼마를 아끼는지, 다음 납입액이 어떻게 바뀌는지, 그 숫자가 어떤 조건에서 나온 것인지** 한 화면에서 이해할 수 있게 한다. 채팅 본문은 질문에 대한 결론을 짧게 말하고, 결과 카드는 비교 수치와 조건을 읽기 쉽게 제시한다.

1차 구현 범위는 토리의 **단일 대출 추가상환 시뮬레이션**이다. 같은 사용성 원칙을 다른 질문에도 적용하기 위한 점검과 후속 작업은 아래에 별도로 정리한다. 대환·복합 시뮬레이션의 표시 규칙은 결과 유형이 다르므로 별도로 검토한다. 구현 Jira 이슈 키는 아직 지정되지 않았다.

## 현재 확인한 계약과 문제

- `LoanPrepaymentCalculator`는 만기를 유지하고 추가상환 이후의 약정 상환액을 다시 계산한다. `comparison.items`에 `MONTHLY_REPAYMENT_yyyy_MM`을, `after.details`에 `nextRepaymentBefore`·`nextRepaymentAfter`를 이미 담는다. 상환일 이전 또는 당일의 기존 약정 회차는 양쪽에 공통으로 반영한다.
- `CoachSimulationFactFormatter`는 월별 상환액을 토리의 `facts`에 넣지 않는다. 따라서 토리와 결과 카드 모두 사용자가 궁금해하는 다음 납입액 변화를 답할 수 없다.
- 결과 카드의 `자세히 보기`는 제목과 요약을 다시 보여준다. 계산 조건이나 월별 변화는 보여주지 않는다.
- 토리 사실 목록의 `현재 → 실행 후`는 시뮬레이션이 실제 대출 상환을 실행한 것처럼 읽힐 수 있다. `현재 총 이자` 역시 이미 납부한 이자인지 앞으로 낼 이자인지 불명확하다.
- 중도상환수수료 자료가 없어 계산하지 않는다. 현재 절감액은 **수수료 제외 예상 이자 절감액**이며 실제 순절감액이 아니다. 월중 경과이자도 별도 정산하지 않고 월 단위로 계산한다.

## 사용자에게 보여줄 정보

### 1. 토리 답변: 질문에 대한 한두 문장

추가상환액과 **만기까지 예상 이자 절감액**을 먼저 말한다. 다음 약정 회차의 납입액 전후가 계산되었다면 그 변화도 답한다. 숫자는 서버가 제공한 결과만 사용하며, 총이자 절감액을 남은 개월 수로 나누어 `월 절감액`을 만들지 않는다.

예시(다음 회차 금액은 실제 계산값으로 채운다):

> 100만 원을 추가 상환하면 만기까지 낼 이자가 약 13만 6천 원 줄어들 것으로 예상돼요. 다음 납입일에는 예상 납입액이 {기존 납입액}에서 {변경 납입액}으로 바뀌어요. 중도상환수수료는 포함되지 않았어요.

사용자가 월 납입액을 물었을 때는 **다음 회차 예상 납입액의 전후와 감소액**을 첫 문장에 둔다. 사용자가 총이자를 물었을 때는 이자 절감액을 먼저 둔다. 질문 의도를 판별할 수 없거나 템플릿 응답일 때는 이자 절감액 → 다음 회차 변화 순서로 답한다. 다음 회차가 없으면 전액 상환에 따른 향후 납입 없음으로 설명하고, 값이 누락되면 월 납입액은 계산 결과에서 확인할 수 없다고 말한다.

### 2. 기본 결과 카드: 결론과 비교

| 표시 순서 | 라벨 | 값 |
| --- | --- | --- |
| 1 | 만기까지 예상 이자 절감 | `136,436원` (수수료 제외) |
| 2 | 다음 회차 예상 납입액 | `{기존 납입액} → {변경 납입액}`; 값이 있을 때만 표시 |
| 3 | 다음 회차 납입액 감소 | `{서버 계산 차액}`; 값이 있을 때만 표시 |
| 4 | 추가상환 예정액 | `1,000,000원` |

`다음 회차`는 **추가상환일 이후 첫 약정 상환일**을 뜻하며, 그 날짜도 함께 표시한다. 이 값은 모든 달에 동일하게 줄어드는 금액이라는 뜻이 아니다. 만기 단축은 현행 계산 방식의 결과가 아니므로 표시하지 않는다. 전액 상환으로 향후 회차가 없어지면 `다음 회차` 대신 `추가상환 후 남은 납입 회차 없음`이라고 표시한다.

### 3. 펼쳐 보기: 검증 가능한 근거

`계산 기준 보기`에서 상환 예정일, 계산 기준일, 적용 금리, 기존 만기, 상환 방식, 상환 후 예상 잔액, 만기까지 예상 잔여 이자 전후를 보여준다. 필요하면 월별 상환액 전후를 `MONTHLY_REPAYMENT_yyyy_MM` 항목으로 펼쳐 볼 수 있게 하되 첫 화면에는 모든 월을 나열하지 않는다. 계산값이 없는 항목은 임의로 채우지 않는다.

하단에 `만기는 유지하고 이후 납입액을 다시 계산한 예상 결과`, `중도상환수수료 미포함`, `월중 경과이자 별도 정산 미반영`을 쉬운 말로 표시한다. 수수료 데이터를 확보하기 전에는 `순절감액`을 표시하지 않는다. 변동금리 대출은 현재 금리를 만기까지 유지한다는 가정을 함께 표시한다.

## 다른 질문 유형 점검과 후속 계획

현재 모든 질문에 `사용자가 원하는 답을 먼저, 필요한 정보만` 제공하도록 설정되어 있지는 않다. 숫자 출처 제한, 누락값 되묻기, 짧은 답변 지시는 있지만, 답변과 카드의 정보 우선순위는 질문 유형별로 정해져 있지 않다. 아래 작업은 추가상환 1차 구현 후 같은 기준으로 진행한다.

| 질문 유형 | 현재 확인한 상태 | 사용자에게 먼저 줄 답과 후속 작업 |
| --- | --- | --- |
| 소비 줄이기·저축 변경 | 목표 달성일 사실이 있으면 템플릿이 현재/변경 후 날짜와 단축·지연을 말한다. 카드에는 관련 사실을 모두 나열한다. | `목표 달성일이 얼마나 바뀌는지`를 먼저, 현재/변경 후 날짜와 배분 가정은 다음에 둔다. 사용자가 월 지출·저축 변화만 물으면 해당 금액을 먼저 답할 수 있는지 서버 결과를 확인한다. |
| 목표 달성일 조회 | 목표 금액·모은 금액·남은 금액·저축 속도·목표일·예상일이 모두 카드에 나온다. 템플릿은 이 조회의 핵심 예상일 문장을 만들지 못한다. | `예상 달성일`, 목표일 대비 빠름·늦음 또는 현재 속도로 달성 불가를 먼저 답한다. 상세 수치는 펼쳐서 본다. 템플릿도 같은 결론을 만든다. |
| 향후 소비 예측 | 3개월의 예상·범위·추세·계절·작년 실적이 카드에 모두 나열된다. 템플릿은 첫 달만 말한다. | 물어본 달의 예상 변동 소비와 가장 큰 근거 하나를 먼저 답한다. 물어본 달을 특정하지 않았다면 다음 달을 기본으로 밝힌다. 나머지 달과 예상 범위는 상세로 보낸다. |
| 최근 진단 | 종합 상태·문제 수·상위 5개 문제가 카드에 나온다. 템플릿은 진단 내용을 요약하지 못한다. | 종합 상태와 가장 중요한 문제 1개를 먼저 설명하고, 나머지 문제는 펼쳐서 본다. 문제가 없으면 `특별히 발견된 문제가 없어요`처럼 빈 결과를 명확히 알린다. |
| 대환·복합 | 이자·금융비용·목표 날짜 등 여러 사실이 같은 카드에 섞일 수 있다. 답변 규칙은 유형별 우선순위를 정하지 않는다. | 대환은 예상 이자 절감과 적용 금리·비용 가정, 복합은 각 행동의 결과와 전체 계산 범위를 구분한다. 계산하지 않은 전체 효과를 합산하거나 추정하지 않는다. |
| 정보 부족·실행 실패 | 누락 입력을 되묻고 도구 실패 사유를 전달하는 경로는 있다. | 필요한 입력 **하나씩** 쉬운 말로 묻고, 실패 사유 뒤에 사용자가 취할 다음 행동을 제시한다. |

공통 표시 규칙은 `질문에 대한 한 문장 결론 → 핵심 비교 최대 2~3개 → 필요할 때만 상세 근거`로 정한다. AI 답변과 템플릿이 같은 결론을 낼 수 있어야 하며, 카드의 기본 영역도 질문 유형에 따라 달라져야 한다. 현재 프롬프트의 `세 문장·200자`는 권고이고 초과 시 로그만 남으므로, 실제 화면 가독성은 별도 검증이 필요하다. 추천 질문은 현재 고정 문구가 많으므로 질문을 누르면 해당 데이터에서 답할 수 있는지 함께 점검한다.

## 구현 작업

### 백엔드

1. `LoanPrepaymentCalculator`의 `after.details`에 추가상환일 이후 첫 약정 상환일을 명시한다. 기존 `nextRepaymentBefore`·`nextRepaymentAfter`와 같은 회차에서 가져와야 한다. `CoachSimulationFactFormatter`는 **단일 `LOAN_PREPAYMENT` 결과에 한해** 세 값을 검증해 사용자용 사실로 추가한다. 월별 목록 전체를 모델 입력에 넣지 않는다.
2. `CoachPromptFactory`와 `CoachTemplateWriter`에 질문 우선순위, `예상` 표현, 수수료 제외 안내를 반영한다. 모델이 새로운 월평균·순절감액을 계산하지 않도록 한다. 템플릿과 AI 응답이 같은 사실을 근거로 답하도록 숫자 가드를 유지한다.
3. 시뮬레이션 계산기, `CoachSimulationFactFormatterTest`, 채팅 API·템플릿 테스트에 부분 상환, 전액 상환, 미래 상환일, 다음 회차 없음, 필드 누락을 추가한다. 표시한 감소액과 날짜가 실제 상환 일정과 일치하는지 확인한다.
4. 구현 시 `backend/docs/ai-coach.md`에 facts 라벨·응답 규칙을 갱신한다. 시뮬레이션 계산 정책을 바꾸는 경우에만 `backend/docs/simulation.md`도 갱신한다.

### 프론트엔드 연동 필요 사항

저장소 기본 작업 범위에 따라 이 계획에서는 프론트엔드 파일을 수정하지 않는다. 구현 이슈에서 프론트엔드 변경이 명시되면 `CoachChatResultCard`를 다음처럼 바꾼다.

1. 기존 사실을 같은 순서로 나열하는 대신 추가상환 결과의 핵심 수치와 다음 회차 변화를 우선 배치한다. 긴 라벨·전후 금액은 모바일 폭에서 잘리지 않도록 세로 비교 형태를 사용한다.
2. `자세히 보기`의 중복 제목·요약을 계산 조건과 월별 내역으로 교체한다. 로딩·조회 실패 시 기본 결과 카드는 그대로 읽을 수 있게 한다.
3. `실행 후`를 `추가상환 시 예상`으로, `현재 총 이자`를 `추가상환하지 않을 때 예상 잔여 이자`로 바꾼다. 실제 상환 처리 버튼이나 완료 상태와 시뮬레이션 표현을 혼동하지 않게 한다.
4. 화면이 `facts`만으로 필요한 표시를 만들 수 있는지 확인하고, 날짜·조건 등 구조화된 값이 더 필요하면 별도 응답 필드 계약을 백엔드와 함께 정한다. 문자열을 파싱해 새로운 금융 계산을 만들지 않는다.

## 완료 기준

- 사용자가 `100만 원 더 갚으면 매달 얼마 줄어?`라고 물으면, 다음 회차 납입액 전후와 감소액을 **실제 서버 계산값**으로 먼저 답한다.
- 사용자가 `이자는 얼마나 아껴?`라고 물으면 만기까지의 예상 이자 절감액을 먼저 답하고, 수수료가 제외되었다고 알린다.
- 기본 카드에서 추가상환액·예상 이자 절감액·다음 회차 변화가 한눈에 보이며, 펼친 영역에서 계산 조건과 월별 차이를 확인할 수 있다.
- 전액 상환·미래 상환일·다음 회차 없음·월별 금액 변동의 경계 사례에서 잘못된 `월 ○원 절감` 또는 만기 단축 문구가 나오지 않는다.
- AI 응답과 템플릿 응답이 같은 사실을 사용하고, `git diff --check`, 관련 테스트, 전체 테스트 및 프론트엔드 정적 검증이 통과한다. 실제 화면에서는 좁은 모바일 폭과 큰 글자 설정의 줄바꿈도 확인한다.
