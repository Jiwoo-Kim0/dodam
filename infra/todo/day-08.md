## 체크리스트

### 1. 통합 리허설
- [ ] EC2에서 `docker compose down` 후 `docker compose up -d --build`로 전체 스택 처음부터 재기동
  - ⚠️ **`down`은 jenkins 컨테이너도 내린다.** Jenkins가 스스로를 재기동할 수는 없으므로 이 리허설은 **호스트에서 직접** 실행할 것 (파이프라인으로 돌리면 중간에 끊긴다)
  - ⚠️ **`down -v`는 절대 금지** — `mysql_data` / `jenkins_home` 볼륨이 삭제되어 DB와 Jenkins 설정(job·자격증명)이 전부 날아간다
- [ ] Nginx → 백엔드 → MySQL/Redis 경로가 정상 동작하는지 실제 API 호출로 확인
- [ ] CI/CD 파이프라인으로 `develop` 브랜치 머지 → 자동 배포까지 end-to-end 1회 리허설
      (Day 2 기준 배포 대상 브랜치는 `develop`. `main` 운영을 시작했다면 그에 맞춰 갱신)
- [ ] 모니터링 대시보드(Grafana)에서 방금 발생시킨 트래픽이 보이는지 확인

### 2. 장애 시나리오 점검
- [ ] MySQL 컨테이너 강제 종료 → `restart` 정책으로 복구되는지, 백엔드가 재연결하는지 확인
- [ ] 디스크 사용량이 임계치에 가까워졌을 때 알림이 오는지(Day 6에서 설정했다면) 확인, 없다면 최소한 수동 점검 루틴(`df -h` 주기 확인) 문서화
- [ ] DB 백업 파일로 실제 복구 리허설 1회 (`mysqldump` → 새 컨테이너에 복원)
      — **복구는 DB 덤프만으로 끝나지 않는다.** 갱신된 ERD가 `VARBINARY` 암호화 컬럼을 쓰므로 **데이터 암호화 키(Day 5)까지 함께 복구**해야 실제로 읽을 수 있다. 리허설에 키 복구 단계를 포함할 것
- [ ] `.env`가 사라진 상황을 가정한 복구 절차 확인 — EC2에만 존재하므로 백업본에서 복원 가능한지

### 2-1. 보안 최종 점검 ([[security.md]] 기준)
- [ ] 외부에서 `https://.../jenkins/` 403, 웹훅은 정상 동작
- [ ] 호스트에 바인딩된 포트가 80/443과 루프백 8080뿐인지 (`ss -tlnp`)
- [ ] backend 컨테이너가 비루트로 도는지 (`docker exec backend id`)
- [ ] 평문 HTTP 시절 시크릿이 전부 로테이션됐는지 (Jenkins 비밀번호, webhook secret, PAT)
- [ ] `develop`이 Protected branch인지
- [ ] `.gitignore`가 여전히 `.env` / `*.pem` / 인증서를 막고 있는지, 레포에 시크릿이 섞여 들어가지 않았는지 확인
      (`git log -p`로 과거 커밋에 실수로 들어간 값이 없는지도 한 번 훑을 것)
- [ ] `security.md`의 "의도적으로 하지 않는 것" 표가 최신인지 — 발표에서 이 근거를 그대로 사용
