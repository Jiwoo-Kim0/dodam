# Day 8 — 통합 리허설, 장애 대응, 문서화 (P0/P1)

8일 스프린트 마무리. 처음부터 전체 스택을 다시 띄워보고, 팀이 이후에도 인프라를 이해하고 다룰 수 있도록 문서를 정리한다.

## 체크리스트

### 1. 통합 리허설
- [ ] EC2에서 `docker compose down` 후 `docker compose up -d --build`로 전체 스택 처음부터 재기동
- [ ] Nginx → 백엔드 → MySQL/Redis 경로가 정상 동작하는지 실제 API 호출로 확인
- [ ] CI/CD 파이프라인으로 `main` 브랜치 머지 → 자동 배포까지 end-to-end 1회 리허설
- [ ] 모니터링 대시보드(Grafana)에서 방금 발생시킨 트래픽이 보이는지 확인

### 2. 장애 시나리오 점검
- [ ] MySQL 컨테이너 강제 종료 → `restart` 정책으로 복구되는지, 백엔드가 재연결하는지 확인
- [ ] 디스크 사용량이 임계치에 가까워졌을 때 알림이 오는지(Day 6에서 설정했다면) 확인, 없다면 최소한 수동 점검 루틴(`df -h` 주기 확인) 문서화
- [ ] DB 백업 파일로 실제 복구 리허설 1회 (`mysqldump` → 새 컨테이너에 복원)

### 3. 문서화
- [ ] `infra/README.md` 최종본 작성: 스택 기동 방법, 포트/도메인 정리, 시크릿 위치 안내(값은 제외), 트러블슈팅 FAQ
- [ ] `00-overview.md`의 "🔲 확인 필요" 항목이 모두 채워졌는지 최종 점검, 못 채운 항목은 "남은 리스크"로 별도 정리
- [ ] 팀 전체가 볼 수 있는 곳(Notion 등)에 인프라 접근 방법(SSH, GitLab CI 변수 등록 방법) 공유 (**사용자 액션**)

### 4. 다음 스프린트로 이관할 항목 정리
- [ ] 8일 안에 못 끝낸 P2(주로 모니터링 고도화, FE OTA, 알림 연동 등) 목록화
- [ ] 리소스 부족으로 축소한 부분(예: Loki 제외 등)과 그 이유 기록 — 나중에 EC2 스펙 업그레이드 시 재검토 근거로 남김
