# QA 결과 기록

Jira의 `[QA]` 이슈를 수행할 때마다 결과를 이 폴더에 md 파일 1개로 남긴다. 팀원 모두가 같은 형식으로 기록해 스프린트별 QA 이력을 한 곳에서 추적하는 것이 목적이다.

## 기록 원칙

- QA 1회 = md 파일 1개. 같은 Jira 이슈를 재수행하면 새 파일을 만들고 이전 파일은 수정하지 않는다.
- Jira `[QA]` 이슈 설명의 요구 항목(시나리오별 통과·실패·진행 불가, 재현 절차, 기대/실제 결과, 심각도, 환경)을 모두 채운다.
- 발견 결함은 이 파일에 기록하고 **Jira에 버그 이슈를 별도 등록**한 뒤 키를 적는다. 결함을 이 폴더에서만 관리하지 않는다.
- 검증하지 못한 시나리오는 통과로 표기하지 않고 `진행 불가`와 사유를 적는다.
- 카드번호·계좌번호·토큰·API 키·`userKey` 등 민감정보와 실제 운영 자격증명은 재현 절차와 캡처에 남기지 않는다. 시연 seed 계정만 사용한다.
- 인코딩은 UTF-8, 줄바꿈은 LF를 유지한다.

## 파일 이름

```
YYYY-MM-DD_<Jira키>_<영역>_<차수>.md
```

예: `2026-09-17_S15P21D105-624_BE-B_1차.md`

- `<영역>`: `BE-A` `BE-B` `BE-C` `FE` `INFRA` `통합` 중 하나
- `<차수>`: Jira 이슈 제목의 차수(`1차`, `2차`, …)
- 캡처가 필요하면 `assets/<파일명과 같은 접두어>/` 아래에 두고 md에서 상대 경로로 링크한다.

## 작성 절차

1. Jira `[QA]` 이슈에서 대상 범위와 완료 조건을 확인한다.
2. 아래 템플릿을 복사해 파일을 만들고 환경 절부터 채운다. 기준 커밋은 `git rev-parse --short HEAD`로 기록한다.
3. 시나리오별로 수행하며 결과를 표에 적는다. 실패·진행 불가는 결함 절에 상세를 쓴다.
4. 결함마다 Jira 버그 이슈를 등록하고 키를 표에 넣는다.
5. 파일을 커밋한다. 커밋 메시지는 `docs: <Jira키> <영역> <차수> QA 결과 기록` 형식을 따른다.
6. 아래 "QA 이력" 표에 한 줄 추가한다.

## 결과 파일 템플릿

````markdown
# [<Jira키>] <영역> <차수> QA — <대상 요약>

- 수행일: YYYY-MM-DD
- 수행자: 이름
- Jira: <Jira키>
- 기준 브랜치/커밋: `develop` `abc1234`

## 1. 환경

| 항목 | 값 |
| --- | --- |
| 서버 | 로컬 / 개발 EC2 / 시연 |
| DB | H2 / Docker MySQL / 시연 seed 적용 여부 |
| 클라이언트 | Android 에뮬레이터 / iOS 시뮬레이터 / Web / Swagger·curl |
| 계정 | 시연 seed 계정 식별자(이메일·이름 등 비민감 값만) |
| 기준일 | 계산에 기준일이 개입하면 명시 (예: 2026-09-17) |

## 2. 요약

| 전체 | 통과 | 실패 | 진행 불가 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 0 |

한 줄 결론과 배포·시연 가능 여부 판단.

## 3. 시나리오 결과

| # | 시나리오 | 전제 데이터 | 절차 | 기대 결과 | 실제 결과 | 판정 | 결함 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 |  |  |  |  |  | 통과 |  |
| 2 |  |  |  |  |  | 실패 | D-1 |
| 3 |  |  |  |  |  | 진행 불가 |  |

판정은 `통과` / `실패` / `진행 불가` 세 값만 쓴다.
API 대상이면 정상 흐름·입력 검증·인증 실패·소유권 격리·빈 결과·경계값을 시나리오에 포함한다.
계산 결과를 검증하면 계산식과 손계산 근거를 실제 결과 옆이나 부록에 적는다.

## 4. 발견 결함

### D-1. <결함 제목>

- 심각도: Critical / Major / Minor / Trivial
- Jira: <버그 이슈 키>
- 환경: 위 1절과 다르면 명시
- 재현 절차:
  1.
  2.
- 기대 결과:
- 실제 결과:
- 참고: 로그 발췌, 캡처 링크(`assets/...`), 관련 코드 위치

## 5. 진행 불가 사유

| # | 시나리오 | 사유 | 해소 조건 |
| --- | --- | --- | --- |

## 6. 비고

전제와 다른 점, 문서·코드 불일치 발견, 다음 차수에서 확인할 항목.
````

## 판정·심각도 기준

| 판정 | 의미 |
| --- | --- |
| 통과 | 기대 결과와 실제 결과가 일치 |
| 실패 | 기대와 다름. 결함 절에 상세 기록 + Jira 버그 등록 |
| 진행 불가 | 환경·데이터·선행 기능 문제로 수행하지 못함. 사유와 해소 조건 기록 |

| 심각도 | 기준 |
| --- | --- |
| Critical | 핵심 흐름 중단, 데이터 손상, 인증·소유권 우회, 민감정보 노출 |
| Major | 주요 기능 오동작 또는 계산 결과 오류, 우회 불가 |
| Minor | 기능은 동작하나 결과·표시가 일부 틀림, 우회 가능 |
| Trivial | 문구·정렬·스타일 등 동작에 영향 없음 |
